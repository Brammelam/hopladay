# Country/year landing pages

The first landing-page release contains three useful examples, not an exhaustive matrix of countries and languages:

- `/en/norway/2027`
- `/en/sweden/2027`
- `/nl/nederland/2027`

Each page contains a full list of nationwide Public holidays, an example generated by the annual optimizer with a 20-day allowance and the default balanced strategy, exact workdays to request off, clearly defined metrics, and a twelve-month calendar. The calendar uses letter markers and accessible date labels as well as visual styling. Break links jump to the corresponding calendar month. The Netherlands page has Dutch headings, explanations, date labels and holiday names. Norway and Sweden use English content. There are no language-alternate links between different jurisdictions.

`backend/test/fixtures/holiday-{NO,SE,NL}-2027.json` stores the complete public Nager.Date responses fetched on 2026-10-31. Each wrapper records the country, year, source URL and UTC retrieval time. The generator validates the provider response with the version 2 catalog validator and selects only nationwide holidays of type Public. It does not independently hardcode recommendations, infer weekend replacement dates, or depend on network access during generation.

Regenerate all three pages offline from the repository root:

```sh
node backend/scripts/generate-landings.js
node --test backend/test/landing-pages.test.js
```

The generator writes the corresponding `frontend/public/.../index.html` files and `frontend/public/landing-routes.json`. The latter is an allowlist for serving these static pages before the Angular router fallback. The parent frontend build copies public assets; server and sitemap integration use this allowlist separately. No unrelated route should be served from an arbitrary filesystem path.

Tests compare the checked-in HTML with freshly computed engine output, verify holidays, metrics, exact leave dates, canonical URLs, twelve-month calendars, Dutch content and ready-filled optimizer links, and exercise HTML escaping. An optimizer change that alters an example requires regenerating the HTML in the same change.

To refresh the holiday data, deliberately fetch the same source URL, validate its full response, update the fixture wrapper's retrieval time and regenerate. A fresh timestamp without a fresh fetch misrepresents data age. The page identifies its snapshot time and explains that the interactive planner can produce a different result after a source update. Holiday entitlement still depends on regional, municipal and employer rules; a nationwide holiday record is not a guarantee of paid time off for every employee.

The generated pages use matching www canonical URLs and indexable server-readable HTML. They do not include client scripts or require an account to show the example. The planner link preserves the country, year and allowance: `/{lang}/optimize?country={code}&year=2027&availableDays=20`. Premium restrictions are unchanged.
